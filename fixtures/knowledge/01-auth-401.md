title: 401 Unauthorized: what it means and how to diagnose it
tags: 401, unauthorized, authentication, token, expired, invalid_token, bearer
---
Fernwick returns HTTP 401 when the request could not be authenticated. The response body always contains an `error.code` field. The value tells you the cause:

- `token_expired`: the access token was valid but its lifetime has ended. Access tokens live for 60 minutes. The client must obtain a new token with its refresh token or client credentials and retry the request once.
- `invalid_token`: the token is malformed, was revoked, or belongs to a different environment. A sandbox token (prefix `fw_test_`) never works against the production host `api.fernwick.example`, and a production token (prefix `fw_live_`) never works against `sandbox.fernwick.example`.
- `missing_credentials`: the `Authorization: Bearer <token>` header was not sent. Proxies that strip the Authorization header on redirects are a common cause.

To tell an expired token from other causes, ask the customer for the `error.code` from the response body, the `X-Request-Id` response header and the UTC timestamp of the failing call. Support can look up the request ID in the request log to see which cause applied.

Never ask the customer to send the token, API key or client secret itself. Support never needs it to diagnose a 401.
